## Superseding PR

**Title:** Prove /as syscall numbers by ESIL constant propagation over one masked scan ##search

**Description:**

Supersedes #25942 (its commits are squashed in).

- Arch plugins declare their syscall encodings as "bytes mask" hexpairs, like preludes (`RArchPlugin.syscalls`, `r_anal_syscalls`); arm and x86 do. A 32-bit arm session declares both A32 and T32; A64 words are little-endian whatever `cfg.bigendian` says, as the arm64 decoder reads them. Core does one RSearch masked scan; plugins without a table keep the decode sweep (mips, riscv...).
- Each hit is resolved in the instruction set at its address (bits hints, as `r_anal_op` does), then kept only if it is aligned for it and decodes as a trap of exactly the matched length. `/as` no longer depends on which address was decoded last.
- The number is the =SN register, by constant propagation over the ESIL of the instructions reaching the trap (known bits per register slot):
  - conditional ops (`movne`, `csel`, IT blocks) leave the meet of both outcomes; ESIL the evaluator does not model clobbers every register it may assign;
  - an op the decoder leaves untyped (`mrc`, `ssat`, `sel`, `xgetbv`, `lock cmpxchg`, arm64 LSE atomics, `csetm`...) clobbers every register, whatever ESIL it carries: nothing says that ESIL states all it writes;
  - calls clobber the caller-saved set (the calling convention is assumed: r7 survives `bl`), traps what the Linux kernel clobbers (r7/x8 survive);
  - delay slots (mips): the ops in the delay slot of a conditional branch leave the meet (branch-likely annuls them), a delayed call clobbers after its delay slot, and after an unconditional transfer the run restarts past the delay slot.
- Inside functions the value comes from the CFG only. A block that may be entered from outside that CFG starts unknown, like the entry: another function starts there, code or data outside the function refers to it, or a block of another function falls or branches into it. Joins widen after 4 changes, so each block is analyzed a bounded number of times.
- Outside functions the value comes from the straight-line run before the trap, at most 64 minimum-size units back (128 bytes on Thumb) or 64 instructions on the x86 sweep, restarting at unconditional jumps. That run assumes no branch lands between the write and the trap; `aa` gives the CFG-checked value.
- The immediate is the number only in vector-keyed dbs (s110) and on ARM OABI (`swi 0x900000+nr`, `asm.abi=eabi0` from e_flags; a kernel with OABI_COMPAT would decide by a nonzero immediate instead). x86 `int` is the vector; from 64-bit code `int 0x80` enters the i386 table, which the loaded db does not describe, so it is refused. Anything else is refused: the old `aop.val` fallback is gone.
- With `search.in=io.maps*` the domain is the executable sections of the binary each map belongs to; a map no binary owns, or whose binary states no executable section, is searched as is. Explicit regions (`raw`, `bin.sections.*`, ...) are searched as given. Mach-O `__TEXT` data sections carry X from the segment, so they are still scanned.
- `R2_ABIVERSION` 145, for the new plugin field.

What the number rests on: the ESIL of every op the decoder types. Where that ESIL states a value the hardware does not guarantee, the name is wrong. Known cases, all arch-plugin ESIL, not touched here: x86 `cpuid` (fixed vendor constants), arm64 `stxr`/`stlxr` (status 0), arm `vmov r6, r7, d0` and `ldrexd` (r7 not written), x86 `mulx`. Indirect jumps whose targets r2 did not resolve are assumed to leave the function.

`/as` time minus load time, median of 5 runs, shared x86-64 Linux host (noisy: master's libflutter ranged 4.6-6.8s across rounds; hits in parentheses; master a3072b9):

The dropped hits were wrong or unproven:
- libflutter, r2pay-arm32: Thumb `svc 0xNN` read as syscall NN. After `aa`, master prints 40 and 71 of those, this prints none.
- r2pay-arm64: 104 `io_setup` where x8 comes from `ldr x8, [x19, ...]`.
- glibc, 21 without `aa`: 18 set their number before a jump or join; 3 read it from a callee-saved register across `lock cmpxchg`, which the x86 decoder leaves untyped. After `aa`, master prints 507 and this 497: the 10 are that `lock cmpxchg` case (pthread_cond_*, pthread_mutex_*). Typing `cmpxchg` in the x86 plugin would bring them back.
- libexploit.so: its 25 stubs are in `.data` (RW); `e search.in=bin.sections.rw` still finds all 25.

Now found: `mov w8, 93` style arm64 writes, three-operand arm ALU (`sub r7, r0, 1`), `movk`, r7 across an earlier `svc`, DOS `mov ah, 0x4c; int 0x21`, the mips and x86 `syscall_*` fixtures, and mips `addiu v0, zero, N; syscall` (uClibc `libc.so.0`: 26, master 0). Still refused: bionic `ldr r7, =nr` literal loads, and numbers set further back than the window without `aa`.

## Reply to the libflutter question (issue comment 5744823614)

Both counts are false positives, master's 8 included:

1. The candidates came from the io map, and `.rel.dyn` shares the r-x PT_LOAD with `.text`. Master only missed those because of where its sweep started: with `e search.in=bin.sections.r` it prints the same 34.
2. With the number register unknown, `/as` fell back to the `svc` immediate. EABI and Thumb take the number from r7 and ignore the immediate, so `svc 0x36` is not ioctl.

#XXXXX takes the number from r7 (or from `swi 0x9000nn` on OABI), searches only the executable sections, and resolves Thumb and ARM per address. libflutter gives 0 hits in 0.16s, with or without `aa`, and still 0 with its section headers stripped.

## Reply to review 4274426970 ("im mainly interested for perf on arm32/arm64")

In #XXXXX, `/as` minus load time (arm32 is Thumb): libflutter 5.8s -> 0.16s, r2pay-arm32 1.4s -> 0.09s, r2pay-arm64 1.2s -> 0.03s. One masked scan finds the candidates; a candidate outside functions replays at most 64 units before it, so the rest of the section is never decoded. Most of the remaining time is the RSearch scan itself.
