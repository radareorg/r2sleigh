## Reply to the libflutter question (post on #25942; answers your own issuecomment-5744823614 of 2026-09-19)

Both counts are false positives, master's 8 included:
1. The candidates came from the io map, and `.rel.dyn` shares the r-x PT_LOAD with `.text`. Master only missed them because of where its sweep started: with `e search.in=bin.sections.r` it prints the same 34.
2. With the number register unknown, `/as` fell back to the `svc` immediate. EABI and Thumb take the number from r7 and ignore the immediate, so `svc 0x36` is not ioctl.

#NEW takes the number from r7 (or from `swi 0x9000nn` on OABI), searches only the executable sections, and resolves Thumb and ARM per address. On libflutter it gives 0 hits in 0.17s, with or without `aa`.

## New PR

**Title:** Prove /as syscall numbers by ESIL constant propagation over one masked scan ##search

Supersedes #25942 (its commits are squashed in).

- Arch plugins declare their syscall encodings as "bytes mask" hexpairs, like preludes (`RArchPlugin.syscalls`, `r_anal_syscalls`). arm does (A32 and T32 in a 32-bit session), and so does x86. Core does one masked RSearch scan. Plugins without a table (mips, riscv, ...) keep the decode sweep.
- Each hit is resolved in the instruction set at its address (bits hints, as in `r_anal_op`). It is kept only if it is aligned for that instruction set and decodes as a trap of exactly the matched length. So `/as` no longer depends on which address was decoded last.
- The number is the =SN register, found by constant propagation (known bits per register slot) over the ESIL that reaches the trap. Inside functions only the CFG is used. Outside them, the straight-line run before the trap is used: at most 64 minimum-size units (64 instructions on the x86 sweep), restarting at unconditional jumps. That run assumes no branch lands in it, and `aa` gives the CFG-checked value. Conditional ops leave the meet of both outcomes. Unmodelled ESIL, calls and traps clobber the registers they may write.
- The immediate is the number only in vector-keyed dbs (s110) and on ARM OABI (`swi 0x900000+nr`, with `asm.abi=eabi0` taken from e_flags). Anything else is refused, and the old `aop.val` fallback is gone.
- With `search.in=io.maps*`, the search covers the executable sections of each map's binary. A map with no binary or no stated executable section is searched as it is. Explicit regions are searched as given.
- `RArchPlugin` gains a field, so `R2_ABIVERSION` is 145.

`/as` time minus load time, median of 5 runs on an x86-64 Linux host, master -> this (hits): libflutter.so (thumb) 4563ms (8) -> 169ms (0); r2pay-arm32.so (thumb) 1031ms (71) -> 53ms (0); r2pay-arm64.so 926ms (104) -> 35ms (0); libarm64.so 49ms (7) -> 2ms (7); libexploit.so 114ms (25) -> 3ms (0); glibc-2.34 x86-64 1095ms (506) -> 541ms (488); ls-m1 52ms (0) -> 5ms (0).

The dropped hits were wrong or unproven:
- libflutter and r2pay-arm32: Thumb `svc 0xNN` was read as syscall NN. After `aa`, master prints 40 and 71 of these, and this prints none.
- r2pay-arm64: 104 `io_setup` where x8 comes from `ldr x8, [x19, ...]`.
- glibc: 18 hits set their number before a jump or join. After `aa`, both print 507.
- libexploit: its 25 stubs are in RW `.data`, and `e search.in=bin.sections.rw` still finds all 25.

Now found: `mov w8, 93`, three-operand arm ALU (`sub r7, r0, 1`), `movk`, r7 across an earlier `svc`, DOS `mov ah, 0x4c; int 0x21`. Still refused: bionic `ldr r7, =nr` literal loads, and a number set further back than the window without `aa`.

Tests: cmd_search, cmd_search_hit and esil/arm_16 give 210 OK and 6 BR (master on the same db: 186 OK, 24 failed). The new ELF fixtures are in radareorg/radare2-testbins#NEW-BINS.
