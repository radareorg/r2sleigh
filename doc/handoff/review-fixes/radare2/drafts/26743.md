## New PR

**Title:** Declare the fortified _chk prototypes per libc ##types

Supersedes #26743, as the series @trufae proposed there.

`__memcpy_chk` is the C identifier, in libc's reserved `__` namespace. Mach-O adds one more `_` as decoration, and `fill_import()` strips it. The type db keeps normalized keys (`memcpy_chk`), which `type_func_try_guess()` and `trim_lodashes()` already reach, so Linux calls were already typed. The gap was that the records loaded only for Linux. `_chk` is a compiler/libc fortify interface, so one name can have two ABIs: Bionic's `__fgets_chk` and `__fread_chk` take the buffer size last.
- The 8 records with one signature in glibc, Bionic and Darwin (`memcpy`, `memmove`, `memset`, `strncpy`, `strcat`, `strncat`, `vsprintf` and `vsnprintf` `_chk`) move to `types.sdb.txt`. Their keys are unchanged, and the Linux key set is the same. `longjmp_chk` and the glibc stdio records stay in `types-linux`. The move changes the macOS db's hash order, so `noreturn 0` now sorts `tn` (`tn~0x~$`).
- `types-android` gets Bionic's `fgets_chk` and `fread_chk`.
- The generic table gets `stpcpy_chk`, `stpncpy_chk`, `strlcpy_chk` and `strlcat_chk`, which have the same signature in all three libcs.
- `r_type_func_guess()` strips a numeric suffix only from `dll_` names. So `sub.___memcpy_chk_123` no longer resolves to `memcpy_chk`, and `sub.KERNEL32.dll_ExitProcess_32` still resolves. This patch does not depend on the others.
- `db/cmd/types_fortified` covers linux, android, macos and ios, including OS changes within one process. It also checks that `longjmp_chk` stays Linux-only, suffixed `sub.` and unknown names, exact `td` precedence, and `__strlcpy_chk` in cat-macos-arm64.

r2r (db/formats, anal, cmd, json) gives master's results plus the 4 new cases, and the unit suite gives 774 OK. Each commit passes the type tests on its own.
