## Close note (post on #26762, then close)

This has landed. Its only commit, a7a616fe, was also the first commit of #26763, which was squash-merged as a756f85, so both hunks are on master in `libr/util/utype.c`.

On `ts`: the change was aimed at struct members. Now that size_t is a typedef, a `size_t` member has to format as `q`, and `tsj` on the NSString layout covers that. `ts size_t` printing a format is a side effect. `ts` was never struct-only for scalars, though. `ts int` prints `pf d` on master and did before a756f85, because `r_type_format` returns `type.<name>` for any `type` kind. Before #26763, `ts size_t` printed `pf x`; it now prints `pf q` rather than going silently empty after the typedef conversion. If `ts` should be struct/union-only, the check belongs in the `ts` handler (`cmd_type.inc.c`, before `showFormat`), not in `r_type_format`, because `pf`, `tl`, `tp`, disasm and the var code also call it for scalars. That check would also change `ts int`, so it is your call.

The typedef branch in `r_type_format` recurses without bound on a cycle. `r2 -qc 'tk typedef.aa=bb; tk bb=typedef; tk typedef.bb=aa; tk aa=typedef; ts aa' --` segfaults on master. The fix is #NEW-CYCLE.

## Follow-up PR

**Title:** Fix infinite recursion formatting a cyclic typedef ##crash

`r_type_format` formats a scalar typedef by formatting its resolved target (a756f85). `r_type_resolve_typedef` followed at most 8 links and returned the name it stopped on. In a cycle (`typedef.aa=bb`, `typedef.bb=aa`) that name is still a typedef, so `ts aa` recursed until the stack ran out.

The 8-link bound was never a cycle test. A chain of 9 or more links without a cycle also stopped on a typedef, and `type_bitsize` then treated it as a cycle: `tss` of the chain `t10` -> ... -> `t0` -> `int` is 0 on master.

The resolver now follows the chain to its end. The typedef links form a functional graph, so Brent's algorithm finds a cycle exactly, in O(chain) sdb lookups and O(1) memory.
- A cycle resolves to NULL. A chain without a cycle resolves to its first non-typedef name, at any length.
- `TYPEDEF_MAX_CHAIN` (4096) bounds the work; it is not a cycle test. A 4001-link chain resolves and a 5001-link one is refused. Master formats the 5001-link chain by recursing.
- The resolver never returns a typedef, so the "still a typedef" guard in `type_bitsize` is removed. `r_type_format`, `r_type_is_signed`, member formatting, `type_bitsize`, var.c and type.c now get the same answer.

Tests, in `db/cmd/types`:
- A two-name cycle and a self cycle: master crashes, and this branch prints nothing for `ts` and 0 for `tss`.
- The chain above: `ts t10` and `ts t8` print `pf d`, and `tss t10` is 4 (master: 0).

Results: r2r shows master + 2 OK and the unit suite 773 OK. ASan+UBSan and valgrind show no report from the resolver.
