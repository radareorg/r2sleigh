## New PR

**Title:** Cache calling-convention argument locations per function ##analysis

Supersedes #26629.

Argument locations belong to the calling convention, but `r_anal_extract_rarg` re-derived them per instruction (one formatted sdb lookup per slot) and re-resolved the source registers per slot.

- The int and fp argument sequences (32 `r_anal_cc_argloc` results) and `r_anal_cc_max_arg` are cached in `RAnalPriv`, keyed on `fcn->callconv` (interned in `anal->constpool`) plus a cc db generation: once per convention. The layout of `RAnal` is unchanged (sizeof 2176 on x86-64). There is one slot per `RAnal` and no lock, because analysis is single-threaded.
- The generation moves on every cc db change. An sdb hook on `anal->sdb_cc`, set in `r_anal_new`, sees every key write, including `sdb_merge` and `k anal/cc/...`. `r_anal_cc_reset` covers `sdb_reset`, which calls no hook; `tcc-*`, `r_anal_purge` and the non-gperf `r_core_anal_cc_init` now call it. The cached strings are interned, so an entry can go stale but never dangle. No new public API.
- The source and destination registers are resolved once per instruction. A null source name (an immediate) is skipped instead of ending the scan.
- A whole-register slot that the instruction neither reads nor writes is skipped before `is_used_like_arg`. Partial registers still go through `is_used_small_reg_arg`. `is_used_like_arg` takes `in_src`/`in_dst`, computed once at each site.
- The fp-family guard is unchanged, and argument recovery should not change.

callgrind, `aa` on bins/elf/bash: 282,208 `argseq_of` calls, 1 refill (32 `r_anal_cc_argloc` calls), 7.45M Ir inclusive (0.04%). With `fcn` in the key it was 3,322 refills and 280.9M Ir.

Tests, in `db/anal/vars_signatures`:
- Two conventions alternate, with a `tcc` redefinition between `afva` runs. This matches master.
- A `k anal/cc/...` rewrite that the next `afva` has to follow. The old head fails it.
- Both fail when the hook is removed.

Results: r2r shows master + 2 new OK, the unit suite 773 OK, and ASan+UBSan is clean on `vars`, `vars_signatures`, `cmd_tcc`, `cmd_tc`, `cmd_af` and `json1`.
