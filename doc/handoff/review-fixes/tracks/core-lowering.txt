- N2: the INSERT lane mask `~(uintN_t)0` is subject to C integer promotion and erases the root
  owner: r2dec lowering today (fold/op_lower); after P10, r2rewrite typed.rs owns the admissible spelling
  evidence: VERIFIED. crates/r2dec/src/fold/op_lower/implementation.rs:2400-2413 builds `lane_ones = ~(lane_ty)0U`, casts it to dst_ty and shifts it by lsb. When lane_ty is narrower than int (uint8_t or uint16_t), C promotes (lane_ty)0 to int 0, so ~ gives int -1, which converts to all ones at the root width. `root & ~mask` is then 0 for lsb=0, and for lsb>0 it keeps only the bits below lsb. Either way every root bit above the lane is silently erased. siphash24's `xor dl,0xff` renders `RDX_15 = (RDX_15 & ~((uint64_t)~(uint8_t)0U << 0U)) | ...`, which zeroes bits 8..63 of v2. Reproduced (scratchpad/verify/sip): the gcc-O1 and gcc-O2 renderings match the source siphash24 on 0/40 lengths. With only the mask replaced by `~((uint64_t)0xffU << 0U)`, they match 40/40. The construct is latent in 27 more renderings that currently grade `equal` or `ub` (branchy gate_three, bool_relay and sign_xor; flag_materialisation classify and sum_carry; manual_limits out_param_parse, state_machine and table_walk; review sext O0/O1/O2; shapes mixed_touch and shape_stack_buffer; several values.c functions). They pass only because the erased bits are zero or unobserved. In review sext, `RAX_0 & ~mask` = `RAX_0 & 0` currently hides critique:lowering's entry-register read. A uint32_t or uint64_t lane is unaffected, since it is not promoted.
  fix (triage proposal; challenge it): Spell the lane mask at the root's unsigned width before shifting: `((dst_ty)(lane_ty)~(dst_ty)0 << lsb)`, or `((((dst_ty)1 << w) - 1) << lsb)` for w < root width. Better, emit one total helper, r2sleigh_insert_uN(root, lane, lsb), from r2rewrite's typed spelling (P10). Add an exhaustive proof harness over root widths {16,32,64,128}, lane widths {8,16,32} and every byte-aligned lsb that compiles the emitted C and compares it against P-code INSERT semantics. Add a Dylint that rejects emitted C applying `~` (or `-`) to an operand whose type is narrower than int. Expect the fix to move the 27 latent renderings: review sext will then really read the unspecified RAX_0, which critique:lowering sext (c) must refuse. Cost: O(1) per op.
  equivalence keys: tests/corpus/hashes.c::gcc-O1::siphash24, tests/corpus/hashes.c::gcc-O2::siphash24
- N5 (secondary to critique:binding F1): a Store's C access width comes from a value type hint whose width differs from the op
  owner: r2dec (render; consumes r2types facts)
  evidence: VERIFIED. crates/r2dec/src/fold/op_lower/implementation.rs:2027-2030 sets elem_ty = certified_member_type_for_current_store().or_else(|| type_hint_for_var(val)).unwrap_or(uint_type_from_size(val.size)). type_hint_for_var (:1036-1073) returns the signature's parameter type for any value that crates/r2types/src/function_facts/mod.rs:331-346 maps to a Parameter slot, with no check that its width equals var.size. crates/r2dec/src/fold/op_lower/memory_renderer.rs checks the certified fact's width against val.size (:89), but then finalizes the access at elem_ty (:109, called from :161) without comparing size_of(elem_ty) to that width.
