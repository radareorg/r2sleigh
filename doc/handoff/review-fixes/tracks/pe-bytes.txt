- N1: the interface result is narrowed to an INSERT's lane although the base bytes are machine-defined
  evidence: VERIFIED. crates/r2ssa/src/recover_interface.rs:785-803: narrow_zero_extend_input_size treats `Insert(base, x, position 0)` (the arm at :790-793) exactly like IntZExt and returns size(x), whatever the base is. recovered_result uses it at :759. For clang's `xor eax,eax; ...; sete al; ret`, the lift gives RAX_1 = COPY const:0 (the zero idiom as a 64-bit copy) and RAX_2 = INSERT(RAX_1, ZF_5, 0), so the result is declared uint8_t (re-run pdim; the headers of fcn_401180 and fcn_401170). A uint8_t return defines only AL, while the machine defines every byte of RAX (zero above bit 0), so an int caller reads garbage (equiv: eax 0x100 against 0). gcc's `sete al; movzx eax,al` of the same source is a ZEXT and stays `equal`. Two approved proposals repeat the defect. critique:calls F7's lattice states `wl(Insert(base,x,0)) = size(x)`, and critique:lowering's sparse_switch/sext narrow(v) ('smallest w with every byte >= w proven zero') would narrow the same way through known bits. The plan's PE line 'result width ... never from value ranges' already rejects the second; the first must be corrected before PE lands.
  fix: In the PE written-lane lattice, set wl(Insert(base, x, lsb)) = max(lsb + size(x), wl(base)) instead of size(x). wl(base) is the base's own written lane:
- IntZExt of a narrower write gives size(input) (the architectural zero-extension of that write, as in F7).
- A constant or zero idiom gives the full carrier: the lifter erases a constant's lane (F7), so the carrier is the only sound bound.
- Any other body definition gives its own width.
- Only an entry value of a register that is neither an argument nor preserved (unspecified by the ABI, proven by must-dependence from PE's dep()) gives bottom.

The result width is the max of wl over the returns. Below that, only closed-world caller demand (P7) may narrow. Known-zero bytes (value ranges or known bits) never narrow a result, because a C return narrower than the machine's written lane does not reproduce the zero bytes. Delete narrow_zero_extend_input_size.
