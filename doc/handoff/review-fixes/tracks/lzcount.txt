USER TASK (verbatim, binding):
## Goal
`r2il::R2ILOp::Lzcount` (and `r2ssa::SSAOp::Lzcount`) has no machine projection and no rendering. Every function whose lift contains it is refused as `native rendering refused: unrepresentable operation` (or, at -O0, `observation journal: ConflictingValue`). Make Lzcount a first-class machine expression that renders as a total C helper, as `PopCount` already does.
## Why
- x86 `LZCNT` lifts to `Lzcount` directly from Sleigh's `lzcount()`, so it is refused today.
- The core-lift track (branch `track/core-lift`, commit "BSF, BSR and TZCNT are lifted as the count their p-code loop computes...") lifts BSR as `(w-1) - Lzcount(x)`. That is the canonical closed form of Sleigh's BSR loop. So `__builtin_clz*` code (BSR) is now refused only because Lzcount does not render.
- Evidence: in an uncommitted experiment, BSR was spelled `PopCount(x | x>>1 | ... | x>>32) - 1`. All six `tests/corpus/values.c::{clang,gcc}-O{0,1,2}::value_count_bits` records then graded `equal` in `tests/equiv/run_equiv.py`. So Lzcount rendering is the only remaining blocker. Do NOT fix this by changing the lift's spelling: Lzcount is the one IL op for count-leading-zeros.
