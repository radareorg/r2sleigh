1. **r2s gains 66 union rows, all from D65.** Over all rows: union-perfect 1,899 to 1,965 of 6,788 (28.0% to 28.9%),
   byte_match 569 to 582, GED perfect 1,547 to 1,611, type_match 328 to 328. r2s stays third on union (kuna 32.0%, ghidra
   29.3% with 26 rows more than r2s, angr 18.8%). It moves from third to second on GED perfect (1,611 against ghidra's 1,605).
2. **Non-bash, 2,736 rows: r2s is third on union, not fourth.** kuna 835 (30.5%), angr 834, r2s 726 (26.5%, was 695),
   ghidra 715 (26.1%). r2s is first on byte_match (218) and third on GED perfect (623 against ghidra 602); it is
   still fourth on type_match (91).
3. **The 66 come from 86 newly rendered functions.** The 2026-10-23 census holds 86 refusals `import stub at 0x...; this
   symbol is the import X and has no body of its own`; this run holds none. Of the 86 rows, 66 are union-perfect
   (GED 64, byte_match 13, type_match 0) and another tool is perfect on 78 (66 on GED). Per project: bash 43, zlib 20,
   libexpat 9, bzip2 6, gzip 6, grep 2, diffutils 0, findutils 0.
4. **No-output goes 380 to 208, not to about 317.** Each newly rendered function removes two rows: its hex-named row
   leaves the table (`0x41950`) and its DWARF-named row gets output. 380 - 2 x 86 = 208. The 317 estimate counted the 63
   wrapper rows once. The other decompilers lose the same 86 hex-named rows (kuna 190 to 104, ghidra 323 to 237, angr 2,957
   to 2,871), which is why their no-output counts fall too.
5. **The structurer stack changed the text of 50 of the 6,598 functions r2s already rendered and no perfect count.** The
   2026-10-23 build was `origin/structure-tails`, the stack tip of that day. Of the 6,598 functions rendered by both builds, 6,548 have identical text and 50 differ: 4 in line order or the proof
   comment, 10 with more residual markers, 36 in structure or naming (for example a `for (;;)` with two breaks rotated to
   `do { } while (a && b)`). On the 6,598: GED better 2, worse 10; byte_match better 6, worse 8; type_match better 1; newly
   perfect 0 and no longer perfect 0 on all three metrics; gotos 16,576 to 16,577; residual sites 160,780 to 160,829.
6. **No OOM, no lost evaluation, no lost function.** `journalctl -k` since the run start holds no OOM line. Both
   `run_gate.py evaluated` checks passed (34 non-bash and 14 bash binaries). The coverage guard fired for 86 rows, all
   hex-named, none added, no function lost.
7. **Mined set (bzip2, zlib, grep; O2 and O2-noinline) at master, scored with the owner mapping:** 1,595 functions scored,
   261 GED-perfect, mean GED 43.99, total GED 70,163, 3,480 gotos in 507 functions. These replace 206 / 43.795 / 57,153

## Method

* Build: `git archive` of `bench-master` (= `origin/master`) to a snapshot directory on contabo, then
  `cargo build --release -p r2s --features sleigh` into a new target directory.
* Tree: a copy of the 2026-10-23 results tree. The refusal censuses of the earlier runs were deleted from the copy
  (they are named by path, so two trees in one directory are counted twice by `census_decbench.py`).
* Non-bash: `run_decbench.sh --workers 1 --project bzip2 diffutils findutils grep gzip libexpat zlib`; then bash:
  `run_decbench.sh --workers 1 --project bash`. `--workers 1` for both because `run_gate.py workers` reads the 13 MB
  bash C that sits in the tree; four workers were not tried. Bash needs one worker for its evaluation anyway.
* `DECBENCH_ALLOW_DROPS=1`, so the driver's own finalize writes through the coverage guard. The row keys of the old and
  new `function_results.json` were then diffed: 86 dropped, 0 added, every dropped key hex-named
  (bash 43, zlib 20, libexpat 9, bzip2 6, gzip 6, grep 2), each a function the new run renders under its DWARF name.
* `report_decbench.py` exits 65 at the end of each invocation: the baseline is marked invalid, as on 2026-10-23.
* The tables below are `compare_runs.py` (scoreboard and restricted populations) and a script that counts per row set
  (all, non-bash, bash, common, each project) from `function_results.json`. On the old tree it reproduces the
  2026-10-23 tables exactly (1,899 / 2,169 / 1,991 / 1,278 union).

## 2. What moved

* Text of the 6,684 functions in r2s's 48 decompiled files: 6,548 identical, 50 changed, 86 new, none lost. Of the 50,
  4 differ in line order (`pair_*` declarations) or the proof comment; 10 have more `r2sleigh_residual_*` markers (a read
  before its definition has run is now a residual: `rbx_2 = r2sleigh_residual_u64(8)` where the old text had
  `rbx_2 = rbx_5`); 36 differ in structure or naming (do-while rotation of a loop with two breaks, a merged condition, a
  swapped `_next` suffix, renumbered residuals). GED is worse on 10 of the 6,269 scored functions and better on 2; none of
  the 12 is perfect on either build.
* The 86 new functions are the `import stub` refusals of the 2026-10-23 census. `census_decbench.py` over the two sets of
  censuses (6,794 functions each): refusal causes 190 to 104, import stub 86 to 0, native effect obligations 104 to 104,
  coverage 0.972 to 0.985, proven 2,720 to 2,742.
* The mined-set view agrees (section 3): on the 1,569 functions both builds score, perfect 247 to 247, no function newly
  perfect or lost, GED unchanged; 26 more functions are scored; 38 of 1,639 texts changed; refusals 68 to 40.
