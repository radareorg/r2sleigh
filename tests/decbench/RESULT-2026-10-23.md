## Method

* Build: `cargo build --release -p r2s --features sleigh` of `decbench-2` (= `origin/structure-tails`) in
  `/root/db2-target`; 4 m 36 s.
* Non-bash projects: `run_decbench.sh --workers 4 --project bzip2 diffutils findutils grep gzip libexpat zlib`.
* bash: `run_decbench.sh --workers 1 --project bash`, plus a 10 GB swap file on the host. One evaluation worker for r2s's
  bash needs 5.2 GB (measured); four do not fit in 8 GB. The first attempt (four workers) lost the bash evaluation to
  the OOM killer again, which is how the cause was found.
* `finalize_results.py --allow-drops` rebuilt `scoreboard.toml`. Its coverage guard fired on two finalizations (3 slices,
  then 2): 17 rows named by a hex address (functions r2s declined on 2026-10-17) disappeared because the functions are now
  rendered under their DWARF names. Every dropped row is a function newly rendered; no function was lost (4 non-bash,
  13 bash newly rendered).
* kuna, ghidra and angr on bash: `tests/decbench/evaluate_checkpointed.py` calls the driver's own
  `project_source_functions`, `extract_source_cfgs` and DecBench's `evaluate_project` on the stored decompilations,
  one worker, because the driver evaluates only what it has just decompiled. Their decompilations are unchanged.
  angr has output for 1,285 of 4,144 bash rows (the 2026-10-17 timeouts), which is why it ranks last on the full set.
* The scoreboard's universe is every row any decompiler scored, so a row only one decompiler has is a miss for the
  others. The tables below say which rows they cover.

## 2. How type_match is computed (DecBench `ae070b8`)

* Population: every `DW_TAG_formal_parameter` and `DW_TAG_variable` with any `DW_AT_location` of the source function,
  including variables of inlined subroutines and lexical blocks. The return type is not scored.
* Score per function: tp / (tp + fp + fn); perfect is 1.0. A decompiler variable with no source partner costs nothing,
  so a declared but unused local, an extra temporary, or a longer frame costs nothing.
* Correspondence for r2s is the address path (`has_line_address_evidence`, every scored function; the legacy offset
  rule scored 20 zlib functions on 2026-10-17 and none now): a parameter by ABI position when both sides have exactly
  one; a stack variable by offset; then the weighted Dice of instruction addresses (r2s's variable owns the addresses
  of the lines that name it), accepted at 0.1 with a 0.03 margin over the next candidate.
* A source variable with no address, no stack offset and no argument index is `unobservable` and counts as fn.
* Types: signedness and qualifiers are stripped, `uintN_t` and `size_t` map to widths, a width must be exact, a pointer's
  pointee must match, and a struct, union or typedef-to-struct matches only by its DWARF name.

`tests/decbench/type_causes.py` re-runs DecBench's own `TypeMatchMetric` over the checkpoints, asserts each function's
tp/fp/fn equals the stored value (it does for all 22,640 function rows), and records one verdict per DWARF variable.

### The classes, by cause and owner

* **Parameter missing (315 / 85).** 410 of the 812 functions have no residual: the body never reads the parameter
  (`mySignalCatcher(int n)`, `BZ2_bzflush(void *)`, findutils `pred_false`); only a caller or a function-pointer slot
  states it, so this is not a ceiling until r2engine has that evidence. 402 have a residual: a call whose arity is a
  floor (71), an import with no declaration (121: `__errno_location`), a variadic tail (99: `error(0, errno, "%s")`
  drops `name`), another unrendered call (77), a tail transfer not rendered (34: `deflateInit_` is
  `fcn_3480(); return residual`). Owner: r2ssa call contracts (P7) and r2abi (prototypes).
* **Pointer as integer (248 / 103) and library-named type (36 / 20).** The call already states the type and the value
  does not take it: `fatal` passes `(const char *)arg0` to `dcgettext` and declares `uint64_t arg0`; `myMalloc` assigns
  `malloc`'s `void *` result to `uint64_t rax_1`. 156 of the 1,015 non-bash pointer parameters declared as integers are cast to a
  pointer type in their own body. r2abi gives width-only prototypes for the stdio and multibyte imports:
  `uint64_t fclose(uint64_t)`, `fflush`, `fileno`, `putc`, `fputs`, `fopen`, `mbrtowc`, `mbrlen`, `__fprintf_chk(...)`
  (23 imports, 945 renderings), and `error` without `...`. Owner: r2types (a callee parameter's type is evidence
  for the value passed in; a call result takes the return type) over r2abi's prototypes.
* **Integer width (209 / 142).** Declared at the register's width (`wordchar(wint_t)` is `uint64_t arg0` and the
  body reads `(uint32_t)arg0`; local loop counters `int i` are `uint64_t`), or narrowed to the byte the body used
  (`mmed3(UChar, UChar, UChar)` is `uint32_t`; `bsPutBit(Int32 bit)` is `uint8_t`, because of `& 1`). Roadmap W49
  (widths from reads, not demanded bytes) and W50 (a narrow DWARF parameter's extension). Owner: r2ssa (lane widths of
  reads and writes) then r2types.
* **Register locals (138 / 126; 364 greedy).** r2s names one C object per SSA definition (`rax_3`, `tmp_4358_8_1`),
  not one per web: `slide_hash` has four DWARF locals and 17 objects. A source local then overlaps a median of 14
  objects (angr 7) with best Dice 0.23 (angr 0.38), under the 0.1 floor or inside the 0.03 margin. The fix is r2dec
  lowering one object per phi web with r2ssa stating the web; this also shortens the text (bash 13.9 MB against 2.6 MB).
  It is an unproven hypothesis for GED, to be graded by D47.
* **Stack local / frame object (16 / 15).** An address-taken `int bzerr` is `uint8_t frame[40]` read as
  `load_u32(frame + 20)`. Owner: r2ssa frame model (P4), r2types layouts (P9).

## 4. What separates r2s from a GED-perfect function

Per function (`tests/decbench/ged_causes.py`: the block graphs of the source and the rendering, as DecBench's `ged`
builds them; a class is a reading of the graph delta, not a proof). Non-bash, 2,623 scored rows, 1,294 of them
goto-free and not perfect.

* **Size decides.** r2s is perfect on 488 of 593 sources of 0 to 2 blocks, 76 of 309 of 3 to 4, 22 of 300 of 5 to 7,
  4 of 380 of 8 to 11, 4 of 443 of 12 to 19, 0 of 598 of 20 or more. No tool is perfect from 20 blocks (0 non-bash,
  2 of 1,345 over all rows). 82% of r2s's 594 GED-perfect functions have a single-block source.
* **The goto-bound remainder is not a union lever.** 735 non-bash functions still have a goto; another tool is perfect
  on 5 of them. Goto removal is a readability lever now.
* **Residual does not separate the gap.** 46% of the 185 gap rows have residual sites against 48% of all goto-free
  imperfect rows. Compound conditions (75 rows, no other tool perfect) and switches (115, 4) have no shape to copy.
* **The return type does.** 795 non-bash scored rows have a `void` source function; r2s declares `void` for 133
  (17%) and a value for 662. By source size, GED-perfect with `void` / with a phantom value: 1 block 91.5% / 83.8%;
  2 to 4 blocks 45.0% / 21.4% (20 / 117 rows); 5 to 9 blocks 14.3% / 9.5% (7 / 137). Applying the gaps to the 662 gives
  about 35 rows for 1 to 4 blocks (5 to 9 blocks adds about 7 on 7 `void` rows). This is roadmap W47 (an unproven return marked): `cadvise` returns `__fprintf_chk`'s `rax` on one arm
  and `r2sleigh_residual_u64(1)` on the other, three blocks against the source's two.

| any arm ending in `return`, `break` or `continue` as a guard | 71 / 25 | +12 / -1 |
| the three respellings together | 544 / 69 | +27 / -1 |

Total GED over the 2,623 scored non-bash rows (the sum of the `before` and `after` columns of each project's tsv):
`--transform select_both` 102,397 to 98,686 (-3,711; 477 better, 46 worse, +15 perfect, 0 lost) and
`--transform noreturn_guard` 102,397 to 102,305 (-92; 77 better, 27 worse, +12 perfect, 1 lost). The other rows of the
table were not summed.

The empty arm is not a block (the hypothesis is refuted). The guard after a `return` adds nothing to the noreturn guard.
The select respelling spells a branch the machine does not have, which AGENTS rule 8 leaves to an ADR; the noreturn
guard is the same C by the callee's noreturn contract.
